# EnergySphere Excel Reports

Пакетное формирование паспортов присоединений из Excel по форме П-П1.
Источник — выбранный XLSX; SQL-подключение и анализ расхождений не используются.

## Запуск

В папке `dist` находятся автономные программы для Windows 7 / Server 2008 R2:

- `es-reports-amd64.exe` — 64 бита.
- `es-reports-x86.exe` — 32 бита (также работает на 64-битной Windows).

Установка Excel, Go, Python, .NET или браузера для работы программы не нужна.
Excel понадобится только для открытия и печати полученных XLSX.

1. Запустить EXE и нажать «Открыть Excel».
2. Выбрать объект и поиск при необходимости.
3. Установить флажки нужных строк. «Выбрать весь список» и «Снять выбор в
   списке» действуют на видимые строки. Выбор сохраняется при смене фильтра.
4. Указать папку паспортов. Необязательный верхний уровень имени, например
   «Астраханский ГПЗ», добавляется перед обществом, объектом и присоединением.
5. Нажать «Сформировать паспорта». Прогресс показывает обработано/выбрано,
   число готовых файлов и текущее присоединение. «Отмена» завершает текущий
   файл и останавливает очередь; готовые файлы сохраняются.

Шаблон встроен в EXE. В каждом отчёте `Лист1` — форма паспорта,
`исх.данные` — строки A:AF выбранного присоединения, включая следующие
поверки, свидетельства, годы и принадлежность. Отсутствующие поля печатной
формы пусты. Порядок оборудования A/B/C — правило импортера. Даты не
сдвигаются, ведущие нули сохраняются. Для неподдерживаемой комбинации фаз
готовые рисунки подключения скрыты: новую схему программа не придумывает.

Повторный запуск не перезаписывает паспорта: добавляется суффикс исходной
строки. Для Windows 7 сохраняется предел пути 260 символов; слишком длинное
имя выдаёт ошибку конкретного отчёта. Выбирайте короткую выходную папку.

**Печать:** параметры исходного шаблона сохранены. На проверенной машине
они дают 10 страниц A4, включая пустые. Перед печатным выпуском нужно
согласовать разбиение формы или размер бумаги; см. бэклог.

## Сборка и проверки

Нужен Go **1.20.14**, стандартная библиотека, `CGO_ENABLED=0`.
Ветка Go 1.20 — последняя с поддержкой этих ОС:
[Go 1.20 release notes](https://go.dev/doc/go1.20#windows).
Версия 1.26 из обычного PATH для legacy-выпуска не подходит.

```powershell
.\tools\build-legacy.ps1
# Или другой путь к установленному Go 1.20.14:
.\tools\build-legacy.ps1 -GoExe C:\Go\bin\go.exe
```

Скрипт запускает тесты и собирает GUI/консольный вариант для x86/x64.
Он не устанавливает компилятор и не меняет системный PATH. Символы
отладки сохранены для диагностики первого выпуска на старых машинах.

Консольный вариант использует тот же импорт и генератор:

```powershell
.\dist\es-reports-cli-amd64.exe --source C:\Input\book.xlsx --list
.\dist\es-reports-cli-amd64.exe --source C:\Input\book.xlsx --out C:\Reports
.\dist\es-reports-cli-amd64.exe --source C:\Input\book.xlsx --rows 10,16 --out C:\Reports
.\dist\es-reports-amd64.exe --gui --source C:\Input\book.xlsx --out C:\Reports
```

`--rows` — первые **исходные строки** блоков, а не номера списка.
Ошибки консольного запуска дают ненулевой код.

Проверки: `go test ./...`; `tools/smoke-gui.ps1` проверяет настоящее окно,
поиск, сохранение выбора при смене фильтра и одиночную выгрузку.
`tools/verify-source-output.py` независимо сверяет перенесённые ячейки
полного пакета с выбранным источником, не изменяя книги (для разработки
нужен Python с openpyxl). Проверены малый набор, 373 выходных файла и GUI
на текущей машине; запуск на настоящей Windows 7 ещё предстоит.
