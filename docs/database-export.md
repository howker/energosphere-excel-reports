# Выгрузка сведений о БД Энергосферы

## Первый файл: структура

Скрипт `sql/01-export-schema.sql` рассчитан на синтаксис SQL Server 2008 R2 и базу `CSD_Astrakhan`. Он читает только системные каталоги. Размер измерительного архива не определяет размер результата: строки прикладных таблиц не выгружаются.

Получаемый XML содержит:

- все пользовательские таблицы и приблизительное число строк из `sys.partitions`;
- столбцы, типы, длину в байтах, точность, NULL, IDENTITY, COLLATION;
- выражения DEFAULT и вычисляемых столбцов, ограничения CHECK;
- первичные и уникальные ключи, индексы, порядок ключевых столбцов, включённые столбцы;
- внешние ключи с попарными соответствиями столбцов, включая составные ключи и правила DELETE/UPDATE;
- описания таблиц и столбцов `MS_Description`, если они есть;
- имена представлений, процедур, функций, триггеров и синонимов;
- зависимости выражений, которые SQL Server зарегистрировал в системном каталоге.

Скрипт требует эффективного права `VIEW DEFINITION` на всю базу и останавливается, если его нет. При ограниченной видимости системные каталоги могли бы выдать только часть структуры. Если возникла ошибка доступа, следует прислать её текст, а не самостоятельно менять права. Для просмотра `sys.sql_expression_dependencies` также требуется право SELECT на это системное представление.

Внешние ключи показывают только формально объявленные связи. Связи, которые существуют только в логике приложения, динамическом SQL или соглашениях об именах, могут отсутствовать в каталоге. После получения структуры такие связи нужно проверить по коду/данным. Пустой список FOREIGN KEY не означает, что таблицы никак не связаны.

Файл является описанием для анализа, а не резервной копией или полным DDL для восстановления. Тела процедур/представлений и все специальные настройки объектов в него не входят.

## Как получить XML в SSMS

1. Перенести файл `sql/01-export-schema.sql` на компьютер, где открыт SSMS, и открыть его в редакторе запросов нужного сервера.
2. Включить **Results to Grid / Результаты в сетку**: `Ctrl+D`.
3. До выполнения открыть **Query → Query Options → Results → Grid**. В разделе **Maximum Characters Retrieved** для **XML data** выбрать **Unlimited**. В некоторых версиях настройка доступна также через **Tools → Options → Query Results → SQL Server → Results to Grid**.
4. Выполнить скрипт (`F5`). В результате ожидается одна строка с колонкой `SchemaXml` и XML-ссылкой.
5. Нажать XML-ссылку. В открывшейся вкладке XML выполнить **File → Save As / Файл → Сохранить как** и сохранить `CSD_Astrakhan_schema.xml`.
6. Передать XML в чат. При необходимости можно упаковать его в ZIP. Не использовать копирование строки из сетки или Results to Text для большого XML: ограничения отображения могут обрезать документ.

Скрипт не создаёт файл на сервере автоматически. Файл сохраняется клиентом SSMS, что не требует запуска команд ОС из SQL Server.

## Если нужен DDL для воспроизведения структуры

В SSMS есть штатный мастер: **база → Tasks / Задачи → Generate Scripts / Создать скрипты**.

Выбрать все необходимые объекты базы; сохранение одним файлом Unicode. В дополнительных параметрах выбрать **Schema only / Только схема**, целевую версию **SQL Server 2008**, включить первичные/внешние/уникальные ключи, CHECK, DEFAULT, индексы и триггеры. Названия и расположение опций зависят от версии SSMS. Такой `.sql` полезен для воссоздания объектов; на производственном сервере нужно только сгенерировать и сохранить файл, а не выполнять полученные CREATE-команды.

Документация Microsoft: [Generate Scripts Wizard](https://learn.microsoft.com/en-us/sql/ssms/scripting/generate-and-publish-scripts-wizard?view=sql-server-2016).

## Почему «вся база за два дня» требует отдельного плана

Фильтр за два дня не является универсальным способом уменьшить БД:

- справочники объектов, присоединений и паспортные атрибуты могут не иметь даты; оборудование, внесённое несколько лет назад, остаётся нужным сегодня;
- дата измерения, дата изменения, дата поверки и дата создания — разные по смыслу поля; выбирать первое поле datetime автоматически нельзя;
- текущие паспортные значения могут обновляться в существующей строке без сохранения истории;
- даже два дня архива для всех измерительных точек могут содержать много строк;
- дочерние строки выбранного периода могут ссылаться на родительские строки более раннего периода; для восстановления связной копии нужен дополнительный отбор родителей;
- обычный BACKUP DATABASE создаёт резервную копию базы, а не произвольный отбор строк по дате.

Для генератора паспортов прежде всего нужны справочники и паспортные атрибуты. После анализа XML составляется список нужных таблиц, определяется их объём и выбираются полные справочники либо связанный набор по нескольким присоединениям. Архив измерений за два дня добавляется только если он нужен для конкретных полей отчёта.

Выборка данных должна иметь явно заданные границы времени и список таблиц. По структуре можно проверить подходящие индексы. Если размер нужно ограничивать выборкой или TOP, результат должен быть обозначен как образец, а не как полная выгрузка периода.

## Проверка подготовленного скрипта

Использованы системные каталоги и вложенный `FOR XML PATH(...), TYPE`, без синтаксиса JSON, STRING_AGG или иных новых возможностей SQL Server. Проведена статическая проверка структуры скрипта. Выполнение на SQL Server 2008 R2 пока не проверено: экземпляр БД здесь недоступен. Окончательная проверка — выполнение пользователем и анализ возвращённого XML или текста ошибки.
