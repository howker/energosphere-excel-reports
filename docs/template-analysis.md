# Анализ шаблона П-П1.xlsm

Дата анализа: 08.10.2026. Источник: `D:\П-П1.xlsm`, 139 940 байт.
SHA-256: `c3c7b34ac41e12c49f8242ef6a30f0cef8888d3b63dd428671ed28c5192d5dc2`.

## Назначение и основной вывод

Книга представляет паспорт-протокол измерительного комплекса: паспортные данные счётчика, трансформаторов тока (ТТ) и напряжения (ТН), поверки, схемы подключения, сведения о пломбах и допуске к эксплуатации.

Основное наполнение — справочные и паспортные сведения Энергосферы. Для этих сведений нужна структура объектов и их атрибутов. Известная по переданному досье таблица архивных измерений `dbo.PointMains` сама по себе не даёт необходимых паспортных полей. Конкретные SQL-таблицы и связи справочников ещё не установлены. SQL-запросов и параметров соединения в этой книге нет.

В образце одно присоединение, его название находится в `исх.данные!C3`. Это исходный кандидат для имени выходного файла. Обработка одинаковых имён и недопустимых символов Windows должна быть определена отдельно.

## Расчёты и движение данных

1. Печатная форма получает паспортные сведения из `исх.данные`.
2. Адрес установки и название присоединения формируются из D3, E3, C3.
3. Класс точности активной энергии извлекается из строки K3 функциями `MID` и `SEARCH`. Реактивный класс в печатной форме пока задан константой 0,5.
4. Типы, номера и даты ТТ разделяются на фазы A/B/C. В образце исходные строки содержат `ф. A - ...` и `ф. C - ...`, а отсутствующая фаза B получает `-`.
5. ТН обрабатываются аналогично. Значение без фазовых маркеров повторяется для всех трёх фаз: это правило текущего шаблона, которое нужно подтвердить для разных конструкций ТН.
6. Коэффициент ТТ отображается как `T3 * 5 / 5`: исходные 10 становятся `50/5`. Коэффициент ТН отображается как `AE3 * 100 / 100`: исходные 100 становятся `10000/100`. Вторичные 5 А и 100 В зафиксированы формулами, поэтому другие номиналы требуют отдельного правила.
7. Следующая поверка рассчитывается прибавлением межповерочного интервала к году даты поверки. Проверенные сохранённые результаты: счётчик — 05.08.2033, ТТ — 17.02.2034, ТН — 23.07.2029. Эти даты находятся на исходном листе и не выводятся в отдельные поля печатной формы.
8. Номера Госреестра и развёрнутое название подстанции выбираются из `Лист2` через `VLOOKUP`.

Основные функции: `IF`, `IFERROR`, `ISERROR`, `SEARCH`, `MID`, `RIGHT`, `LEN`, `DATE`, `YEAR`, `MONTH`, `DAY`, `CONCATENATE`, `VLOOKUP`. Универсальный Excel-движок не обязателен, если приложение явно реализует эти конкретные преобразования и заполняет готовые результаты.

## Макрос и схемы

Извлечены пять VBA-модулей. Единственная исполняемая процедура находится в модуле основного листа: `Private Sub Worksheet_Activate()`. Другие модули содержат только служебные атрибуты. В извлечённом VBA-коде обращений к SQL или внешним программам нет.

Макрос запускается при активации основного листа и переключает видимость объектов `Рисунок1`, `Рисунок2`, `Рисунок3`:

| Условие по `Лист1` | Видимый объект | Содержание рисунка |
| --- | --- | --- |
| M13 = `A, C` и R10 = `-` | `Рисунок3` | Два ТТ, два ТН |
| M13 = `A, C`, первое условие не выполнено | `Рисунок2` | Два ТТ, три ТН |
| Все остальные случаи | `Рисунок1` | Три ТТ, три ТН |

M13 зависит от наличия ТТ фазы B; R10 — от типа ТН фазы B. Для образца выбран `Рисунок2`, и сохранённая видимость объектов соответствует этому правилу.

В основном листе также есть отдельный скрытый объект `Рисунок 3` с пробелом в имени. Он не входит в переключение макроса. Нельзя сопоставлять рисунки только по похожим названиям.

Макрос можно заменить установкой видимости нужных объектов при генерации. Меняется состояние drawing XML; сами изображения, векторные схемы и их привязки следует сохранить. Ветка «все остальные случаи» не проверяет полноту фаз A/C и конфигурации, отличные от двух перечисленных: такая проверка нужна в приложении.

## Ошибки и ограничения шаблона

| Место | Наблюдение | Последствие / действие для разработки |
| --- | --- | --- |
| `Лист1!A16` | `VLOOKUP(исх.данные!B3,пс,2)` без четвёртого аргумента | Приблизительный поиск. В образце источник `РП 10 кВ №4`, точного совпадения в D4:D22 нет, сохранённый результат — ПС «Подземное хранилище». Нужен точный поиск и подтверждённое сопоставление названий; простая замена на точный поиск выявит отсутствующий ключ, но не заполнит его |
| Восемь `VLOOKUP` на `Лист1` | У всех пропущен режим точного совпадения | Неизвестный тип оборудования может получить номер Госреестра соседнего типа. Перед точным поиском нужно убрать пробелы и переводы строк из разобранных фазовых значений |
| `Лист1!V13` | Формула проверяет пустую R9 и берёт пустую V6 | В сохранённом результате интервал поверки фазы B равен 0, тогда как для ТН других фаз — 5 лет. Вероятный правильный источник — `исх.данные!AC4`; подтвердить при исправлении |
| `Лист1!V10`, `T13` | Признак отсутствия фазы проверяется по пустой R9 | Проверка не обращается к типу ТН фазы B в R10; при других данных возможны неверные поля |
| `Лист1!Q1` | Заголовок «Трансформаторы тока», но поля идут из группы `*_TU` | Верхний раздел фактически описывает ТН. Заголовок требует исправления |
| Разбор фаз | Поиск строковых маркеров и ограничение длины фрагментов до 30 символов | Возможны обрезка длинных типов, остаточные переводы строк, нераспознанные обозначения фаз. Нужен нормализующий разбор с явным результатом для отсутствующей фазы |
| Даты | Входные даты представлены строками `ДД.ММ.ГГГГ`; `YEAR/MONTH/DAY` используют их как даты | Пересчёт зависит от распознавания дат Excel. В Go даты следует разбирать явно; отдельно проверить 29 февраля при прибавлении лет |
| `Лист1!P7` | Реактивный класс точности задан числом 0,5 | Он не изменится при другом `КлТq` в атрибуте `Q` |
| `Лист1!B44` | Текст содержит дату ввода 25.12.2006 | Копирование всем присоединениям создаст неподтверждённые паспортные сведения |
| Поля нагрузок, погрешностей, приборов и пломб | В шаблоне есть фиксированные значения 50 ВА, 4,3 ВА, 0,4 ВА, 0,06 ВА, прибор и его номер, погрешности, формулировка допуска и другие тексты | По формулам они не вычисляются из БД. Требуется определить общие настройки, индивидуальные поля и данные, которые должны оставаться незаполненными |
| Номер протокола, дата составления, подписи | В образце не заполнены | Правила заполнения ещё не определены |

Сохранённые значения дают возможность проверить образец, но после замены входных данных они станут устаревшими. Нельзя выдавать скопированные кэши формул как расчёт нового присоединения.

## Предлагаемая реализация генератора

Это проектное предложение по результатам анализа; приложение в рамках этого анализа не создано.

1. Получить из справочников Энергосферы стабильный ID присоединения, его иерархию и 18 паспортных атрибутов. Пока схемы нет, не выдумывать JOIN и SQL-имена по отчётным кодам.
2. Собрать объект данных: счётчик, ТТ по фазам, ТН по фазам, объект/РУ/шины, дополнительные подтверждённые сведения. Нормализовать пробелы, переносы строк, даты и отсутствующие значения. Серийные номера хранить строками.
3. Вычислить конкретные производные значения средствами Go, с точным поиском в справочниках и явными сообщениями об отсутствующих данных.
4. Использовать копию исходного шаблона как ZIP/Open XML. Менять только нужные ячейки и видимость схем, сохраняя стили, объединения, картинки, составные векторные объекты и настройки печати. Полное пересоздание книги требует отдельной проверки сохранности этих объектов.
5. Определить формат результата: XLSM с сохранением VBA либо XLSX с корректным удалением VBA и связанных записей пакета. Выбор ещё не принят. Если сохраняются формулы, записывать согласованные вычисленные кэши и настройки пересчёта; если выдаются только значения, отдельно согласовать возможность потери дальнейшего пересчёта в Excel.
6. Формировать один файл на присоединение. Обработать запрещённые символы, завершающие точки/пробелы, зарезервированные имена Windows и совпадения названий. Стабильный ID нужен для предотвращения смешения одноимённых присоединений; правило имени файла требует согласования с требованием пользователя.
7. Перед массовым запуском сравнить один сгенерированный паспорт с эталоном: каждое поле, фазовую схему, изображения и печать. В журнале отдельно учитывать пропуски атрибутов и справочников. Не подставлять данные образца вместо отсутствующих данных нового объекта.

## Что требуется установить дальше

- SQL-таблицы объектов, их иерархии, определений атрибутов и значений; ключи и связь с присоединениями.
- Где именно хранятся коды `TY`, `SN`, `DT_QC`, `MPI`, `Q` и группы `*_TA` / `*_TU`.
- Что означает `47462` и как выбираются все электрические присоединения.
- Получается ли один паспорт на присоединение при нескольких точках/счётчиках, либо требуется выбор действующего оборудования.

## Проверка и границы анализа

Проверены структура ZIP/Open XML, ячейки и сохранённые значения всех четырёх листов, 100 формул, описания 23 входных полей, имена диапазонов, VBA-исходники, рисунки и их видимость. Макросы не выполнялись. Подключений к промышленной БД не было. Исходный XLSM не изменён; в репозиторий исходная книга и извлечённые паспортные данные не добавлялись. Создан только этот документ анализа.

Построен вспомогательный просмотр формы через Artifact Tool. Движок просмотра не обработал часть исходных формул с кириллическими ссылками: появились `#NAME?`/`#VALUE!`, которых нет в сохранённых значениях исходника; часть графики также не отобразилась. Такой просмотр не является проверкой поведения или печати в Excel. Для окончательной проверки нужен Excel с подготовленным результатом.
